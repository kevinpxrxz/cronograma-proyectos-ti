Criterios de aceptación

Una frase por criterio que diga qué se espera de la funcionalidad. Ej.: «Como usuario, debo poder acceder al portal con mi usuario y contraseña.»

Conectar una IA

La IA lee cada historia (descripción, criterios y mockups) y te indica las ambigüedades: términos vagos, criterios que no se pueden probar, información que falta, contradicciones, casos no cubiertos y diferencias con los mockups. También compara las historias entre sí, propone criterios faltantes y preguntas para el negocio, y puede corregirlas. Usa la IA que prefieras.

Se usa el modelo Claude Opus 5.5.

¿Prefieres no conectar una IA? Pulsa Copiar para cualquier chat: se copian las instrucciones y tus historias pendientes para pegarlas en ChatGPT, Gemini, Copilot, Claude u otro chat de IA. Las imágenes adjúntalas tú en ese chat.

Conexión con Azure DevOps

Cada historia se crea como un elemento de trabajo en el tablero de tu proyecto, con sus mockups como adjuntos. Si cambias una historia y la vuelves a subir, se actualiza el mismo elemento y sus criterios de aceptación se reemplazan por completo, así no quedan criterios antiguos.

Créalo en Azure DevOps → User settings → Personal access tokens, con el permiso Work Items: Read & write. Solo se envía a Azure DevOps.

Corregir con IA

Si la IA dejó preguntas, aparecen aquí: escribe la respuesta después de cada flecha. Lo que no respondas quedará como [POR DEFINIR].

Revisa la propuesta. Si la aplicas, se reemplazan la descripción y los criterios de la historia. Si ya estaba en Azure DevOps, quedará como «tiene cambios sin subir».
